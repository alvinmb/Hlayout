Two ways in

# 1. The command bar (bottom of the GUI) -- type a line, press Enter
# Up/Down recalls your last 10 commands (shared with the Script Console)
RECT 0 0,0 100,50
SREF VIA_Layer1_to_Layer3 200,0

# 2. Python, headless or via the built-in Script Console (name: hl)
from hlayout.scripting.api import Session
s = Session.new("MYLIB")
s.new_cell("TOP")
s.rect(layer=0, x1=0, y1=0, x2=100, y2=50)
s.save("out.gds")

Connecting Claude (MCP server)

HLayout ships an MCP server, so an MCP client such as Claude can drive the layout as a set of tools. The client starts the server itself; it is standard-library Python and talks over stdio:

python -m hlayout.mcpserver [--headless] [--design path.gds]

Live — tick Tools → MCP Server (Claude) in a running HLayout window (or launch with python hlayout_app.py --mcp, or set HLAYOUT_MCP=1). Tool calls then run inside that window: edits show on the canvas and go into the normal undo history. Untick the menu item to stop it; the status bar shows MCP bridge on (127.0.0.1:port) or MCP bridge off.

Headless — with no window listening (or with --headless) the server works on its own in-memory session, and nothing appears on screen. Every reply says which of the two was used whenever that changes.

The bridge is off until you ask for it, because it lets a local process run Python inside the app. It listens on 127.0.0.1 only, on a random port, and every request must carry a per-run token; both are written to ~/.hlayout/mcp_bridge.json and removed when the bridge stops. Each start uses a new port and token, and the server re-reads them on every call, so Claude does not need restarting.

Claude Code picks the server up from .mcp.json in the HLayout folder. For the Claude desktop app, add this to claude_desktop_config.json (with your own path):

{"mcpServers": {"hlayout": {
  "command": "python",
  "args": ["-m", "hlayout.mcpserver"],
  "env": {"PYTHONPATH": "C:\\dev\\HLayout"}
}}}
